# 执行度对账（Post-Shot Review · 试片会）

> 用途：每次真机生成后，强制复盘「哪些 prompt 生效了、哪些被模型吞了」——形成写→拍→改闭环。  
> 动机：真机验证发现「5 段运镜只执行 3 段」——不复盘，同样的坑下次还踩。  
> 铁律：**每次真机跑完，下一镜的 prompt 必须基于对账结果修正**，不允许带着旧 prompt 继续。

---

## 1. 对账时机

| 时机 | 动作 |
|------|------|
| **每次真机生成后** | 跑对账表（见 §2），修正下一镜 prompt |
| **每次用户说「不对劲/换个方式」** | 强制先对账再改（不猜） |
| **发布/金样更新前** | 用最新对账结果校正金样 |

---

## 2. 执行度对账表（生成后必填）

```text
【执行度对账 · {task_id} · {模型}】
| Prompt 段 | 预期 | 实际执行 | 判定 | 修正 |
|-----------|------|----------|------|------|
| 运镜 P1（缓推） | 0-3s 缓推 | ✅/❌/部分 | PASS/FAIL | 下镜改… |
| 运镜 P2（环绕） | 3-6s 环绕 | … | | |
| 微动（衣袂） | 6-9s 一次 | … | | |
| 光相位（月冷光） | 5-10s 渐强 | … | | |
| 真声轨（檐铃） | 9-12s 一声 | … | | |

【结论】执行度 X/5 段。下镜修正：…
【决定】□ 逐拍生成（执行度<3/5 时强制）□ 降级单主运镜 □ 维持
```

---

## 3. 判定规则

| 执行度 | 判定 | 下镜动作 |
|--------|------|----------|
| ≥4/5 | ✅ 高执行 | 维持同写法 |
| 2-3/5 | ⚠️ 中执行 | **切逐拍生成（A+）** 或降级为 1 签名 |
| <2/5 | ❌ 低执行 | 强制逐拍；单条 prompt 拆成 2-3 段 |

**执行度 = 判定来源，不靠感觉。** 抽帧看运镜轨迹对表（每拍抽 1-2 帧即可）。

---

## 4. 反哺机制

- 对账结论写入 `research/`（如 `research/10-execution-audit.md` 追加）
- 金样按对账修正：哪段 prompt 生效保留，哪段被吞改写
- **模型画像**：记录「H3 丢中段运镜」「Seedance 遵从度高」等，编译时选模型参考

---

## 5. QC 闸门

- [ ] 真机生成后执行度对账已填（task_id 记录）  
- [ ] 执行度 <3/5 → 已切逐拍或降级（未硬撑）  
- [ ] 下镜 prompt 已按对账修正（未带旧 prompt 继续）  
- [ ] 对账结论已落 research/（可追溯）
