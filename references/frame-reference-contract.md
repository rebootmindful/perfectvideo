# 首尾帧 + 多参考图 + @槽位变量系统（连戏硬控制 · B 档）

> 用途：把跨镜连戏从「文字焊接 + 祈祷模型记性好」升级为「首尾帧 + 参考图双锚 + **@槽位变量** 硬控制」——连戏从 ~90% → ~99%。  
> 适用：MiniMax-H3（首尾帧 + ≤9 参考图 + 角色/环境分离）、Kling 3.0（首帧+元素参考）。  
> 铁律：**参考图锁身份，首尾帧锁运动起止，@槽位把素材变成变量，文字锁细节**——四者缺一不可。  
> 借鉴：seedance-cinematic-video 的 @槽位系统（角色/场景/道具/音频注册为变量）。

---

## 1. 双锚硬控制模型

| 锚 | 锁什么 | 用什么 |
|----|--------|--------|
| **首帧/尾帧** | 运动起止点（画面从哪开始、到哪停） | `--first-frame` / `--last-frame` |
| **参考图** | 身份/道具/环境的**外观**（不随运动漂） | `--image` 多张 |
| **@槽位变量** | 素材↔prompt 的绑定（谁是谁、谁是环境） | `@人物/@环境/@道具` 注册 |
| **文字锁** | 细节/材质/光（模型不看的字它不会写） | prompts.primary |

**哲学：** 让模型「记得」不如「给它看」。参考图是记忆的外置硬盘，@槽位是硬盘的接线。

---

## 2. @槽位变量系统（多主体连戏的工程化表达）

### 2.1 槽位注册（编译时第一步）

每个素材注册一个槽位名，**prompt 内所有引用都走槽位名**，不写「那个人/那个场景」：

| 槽位 | 绑定 | 例 |
|------|------|-----|
| `@人物` | 主角外观图 | 神女（脸/衣/帽/体态） |
| `@人物2` | 第二主角 | 白鹭 / 男配 |
| `@道具` | 关键物外观 | 油纸伞 / 帽 |
| `@环境` | 主场景 | 云上神域 |
| `@环境2` | 次场景 | 内殿 |
| `@音频` | 参考音频（H3） | 场景环境声 |

### 2.2 槽位引用（进 prompt）

```text
【槽位绑定】
@人物 = 人物参考图（脸/衣/帽不变）
@环境 = 场景参考图（空间/主光不变）
@道具 = 油纸伞参考图

【锁定域 · 禁止改写】
@人物 保持此外观，静立驻足于迎客松旁…
@环境 保持此空间，云海涌动…
@道具 保持此外观，伞面无logo…
```

### 2.3 槽位铁律

- **槽位名全局唯一**；同一角色全片用同一槽位名（跨镜连戏的工程基础）
- **@人物 与 @环境 必须分离**，混传 = 模型分不清谁是谁
- **槽位绑定在 Bible 冻结时声明**，每镜原样带出（NextShot 链自动继承）
- 素材缺失的槽位：标注 `@人物 (待准备)` 并入素材清单
- 槽位 ≤9 图（H3 上限）；超出 → 合并或降级为文字锚
- **"不采用"负面声明（Seedance 原生 · 2026-08-15）**：每个槽位绑定须写明"不采用"什么——`@人物 用于外貌/服装，不采用图片背景`；`@环境 用于空间/光线，不采用图中人物`。模型易把参考图背景/人物误带入成片，负面声明是连戏硬控。多张图同一物体时须声明"`@图1-4 共同定义同一物体，始终只有一个`"。

## 3. 素材准备清单（生成前交给用户）

每次编译前，导演输出一张**素材清单**，告诉用户准备什么：

```text
【素材准备清单】
□ @人物 1 张：神女正面/全身图（jpg/png，清晰，无 logo）
□ @环境 1 张：云上神域主场景（16:9 或竖幅）
□ @道具 1 张（可选）：油纸伞 / 帽饰
□ 首帧 1 张（NextShot 链）：上一镜尾帧
□ 尾帧 1 张（可选）：本镜落幅构图
```

- 清单并入 `output-contract.md` 交付块
- 用户没素材 → 降级纯文生视频（@槽位用文字描述替代）

## 4. 参考图角色合同（与 model-constraints 对齐）

| 角色 | 槽位 | 用途 | 数量 |
|------|------|------|------|
| 人物 | `@人物` | 脸/衣/帽/体态锚 | 1–2 张 |
| 道具 | `@道具` | 帽/伞/产品/关键物 | 1–2 张 |
| 环境 | `@环境` | 空间/主光/材质 | 1–2 张 |
| 首帧/尾帧 | `first/last` | 运动起止点 | 各 1 张 |

**H3 规则：** 参考图 ≤9 张；首尾帧模式与多参考图模式**互斥**（传了 first/last 就不能再传 image/video/audio）——所以**二选一**：

- **A 方案（运动控制优先）**：首尾帧双锚（运动起止锁死，无参考图）
- **B 方案（身份控制优先）**：多参考图（@人物+@环境 锁死外观，无首尾帧）

> 进阶：Kling 3.0 支持「首帧 + 元素参考」并存（比 H3 强），可按需选模型。

## 3. 写作模板

### 3.1 首尾帧方案（A）

```text
【首帧】上一镜尾帧（直接复用，不改构图）
【尾帧】本镜落幅目标构图（如需锁定）

【运镜】从首帧构图起飞，演化到尾帧构图；
单主运镜；中间节拍与首尾帧自然衔接。
```

### 3.2 多参考图方案（B）

```text
【参考】@人物（保持此人物外观不变）
【参考】@环境（保持此世界外观不变）
【参考】@道具（如有时）

【锁定域 · 文字焊接】仍逐字写全（参考图 ≠ 细节锁，文字不能省）
```

---

## 4. 编译规则

- **B 方案**：prompt 里用「图片1/图片2」按传入顺序引用（H3 自然语言引用）
- **A 方案**：首尾帧 = 图生视频，比例自动 adaptive，忽略 aspect_ratio
- **身份锚**：@人物 与 @环境 分开传，**勿混**（混了模型分不清谁是谁）
- **每镜更新尾帧**：NextShot 链中，本镜尾帧 = 下一镜首帧（接续铁律）

---

## 5. QC 闸门

- [ ] 参考图方案声明（A 首尾帧 / B 多参考图 / 无）  
- [ ] @人物 与 @环境 分离，未混传  
- [ ] 文字锁未因参考图而省略（参考图 ≠ 细节锁）  
- [ ] NextShot 链：上镜尾帧 = 下镜首帧  
- [ ] 传了参考图但 prompt 未引用 → 拦截（模型不自动插入）
