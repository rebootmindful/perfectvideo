# 出稿后冲击力审计（Post-Delivery Impact Audit · PIA）

> **定位**：交付产物后、NextShot 之前的**硬门禁**。不可跳过。  
> **目标**：用全网同类镜头的真实拍法，给当前产物一个"大师级对照"，识别差距并给出可落地的提升建议。  
> **铁律**：不搜索就给建议 = 红线违反。用户未确认就改 = 红线违反。

---

## 1. 触发条件

| 时机 | 动作 |
|------|------|
| 交付产物（overview + lock + shotlist + prompts + QC）完成后 | **立即启动 PIA**，不等用户问 |
| NextShot 每镜交付完成后 | 同样启动 PIA（本镜独立审计） |
| 用户说"不用了直接出" | **禁止跳过**——至少执行搜索+建议，用户可以在确认环节选"不采纳" |

---

## 2. 搜索策略（Step 1）

### 2.1 关键词提取

从当前产物中提取 **≥2 个搜索维度**：

| 维度 | 提取来源 | 示例 |
|------|----------|------|
| **场景动作** | shotlist 的核心动作 | "cliff fall rescue hand grab slipping" |
| **运镜技法** | prompts.primary 的运镜段 | "speed ramp slow motion falling cinematography" |
| **情感主题** | overview 的情感弧线 | "letting go sacrifice falling scene emotional" |
| **同类参考** | 题材/类型 | "卧虎藏龙 坠崖 拍摄手法" / "wuxia cliff fall shot" |

### 2.2 搜索执行

```
WebSearch ≥2 维度，每维度 num=5
→ 评估 snippets，选 1-2 个最权威来源
→ WebFetch 获取全文
→ 提取可迁移技法
```

### 2.3 来源优先级

1. **电影技法分析**（cinenoir / studio binder / AFC 等）— 最高权重
2. **AI 视频 prompt 对标**（awesomevideoprompts / seedance 社区）— 同赛道直接参考
3. **导演/摄影指导访谈**— 创作意图层面
4. **学术/教科书**— 理论框架

---

## 3. 分析框架（Step 2）

### 3.1 三维度差距分析

将搜索结果与当前产物逐维度对比：

| 维度 | 审计问题 | 大师参考 |
|------|----------|----------|
| **戏剧化** | 叙事张力够吗？情感有层次吗？角色弧光可见吗？ | Inception：坠落作为叙事节拍器；Enter the Void：坠落=物质消解 |
| **冲击力** | 运镜有超越感吗？速度变化够大胆吗？微观细节有锚点吗？ | Matrix：空气粘滞感；Justice League：芝麻种子微观升华；Sherlock：cinebot 超越时间 |
| **感染力** | 光影有情绪线吗？声画对位精准吗？节奏有呼吸吗？ | Hold My Hand：心跳骤停+闪电脉冲；卧虎藏龙：三远法+低饱和 |

### 3.2 差距识别模板

```text
【差距识别】
维度：{戏剧化/冲击力/感染力}
大师技法：{来源} 的 {具体技法}
当前产物：{当前写法}
差距：{缺了什么}
改进：{可落地的具体写法}
来源：{URL}
```

---

## 4. 建议输出格式（Step 3）

### 4.1 结构化建议表

```text
【PIA 建议表 · bible_version: frozen-vN → proposed-vN+1】

| # | 维度 | 大师技法 | 当前差距 | 建议改进 | 影响拍 | 来源 |
|---|------|----------|----------|----------|--------|------|
| 1 | 冲击力 | Inception 500fps 悬置厄运 | 慢动作缺"重力仍在拉扯"张力 | 超慢段加入重力可见线索 | 拍6-8 | URL |
| 2 | 感染力 | Hold My Hand 心跳骤停 | 声锚缺"停顿一拍" | 拍9加入心跳骤停 | 拍9 | URL |
| ... | ... | ... | ... | ... | ... | ... |
```

### 4.2 每条建议必须包含

- **来源 URL**（实际搜索到的，不可凭空生成）
- **影响拍号**（具体到哪几拍要改）
- **可落地写法**（不是"增加冲击力"这种空话，是具体的 prompt 修改建议）

---

## 5. 用户确认流程（Step 4）

### 5.1 AskUserQuestion 格式

```
问题：PIA 审计完成，发现 N 条提升建议。要采纳哪些？
选项：
1. 全部采纳（推荐）— N 条建议全部落进 prompt
2. 部分采纳 — 告诉我选哪几条
3. 不采纳 — 当前版本冻结，直接进 NextShot
```

### 5.2 确认后动作

| 用户选择 | 动作 |
|----------|------|
| 全部采纳 | 逐条落进 lock/prompts/shotlist，更新 bible_version，diff 标注 |
| 部分采纳 | 只落选中的，未选的存档备注 |
| 不采纳 | 当前版本冻结，PIA 报告随交付附上，进 NextShot |

---

## 6. 执行规则（Step 5）

### 6.1 修改时的铁律

- 修改 lock/prompts 时必须走 **diff 对齐**（见 compile-modes.md 提交 diff 审计）
- 修改后必须重跑 **出稿前逻辑审核**（七维，见 pre-submit-logic-audit.md）
- 修改后必须更新 **bible_version**（vN → vN+1）
- 修改点必须在交付文件中 **标注**（`[PIA 改进 #N]`）

### 6.2 修改不破坏完整性

- PIA 修改是 **增量优化**，不是重写
- 修改只改建议影响的拍/段，不改其他拍
- 修改后 shotlist 拍数不变、运镜段数不变（除非建议明确增减）

---

## 7. QC 闸门

- [ ] WebSearch 已执行（≥2 维度）
- [ ] 每条建议附来源 URL
- [ ] 建议表含三维度（戏剧化/冲击力/感染力）
- [ ] AskUserQuestion 已发起
- [ ] 用户选择已记录
- [ ] 修改后重跑逻辑审核
- [ ] bible_version 已更新
- [ ] 未跳过 PIA 直接进 NextShot

---

## 8. 与其他环节的关系

| 环节 | 与 PIA 的关系 |
|------|---------------|
| 出稿前逻辑审核 | PIA 在逻辑审核**之后**（先审自洽，再审冲击力） |
| 生成策略确认 | PIA 在生成策略确认**之后**（方向/成本已定，再优化质量） |
| NextShot | PIA 在 NextShot **之前**（本镜审完才进下镜） |
| 执行度对账 | PIA 在执行度对账**之前**（先优化剧本，再对账成片） |

```text
完整链路：
编译 → 出稿前逻辑审核 → 生成策略确认 → 交付 → 【PIA】→ NextShot / 执行度对账
```
