# PerfectVideo SPEC 审计报告

**审计身份：** AI 视频脚本创作专家  
**审计对象：** `PERFECTVIDEO-SPEC.md` v0.1.0-scaffold + `SKILL.md` + 关联 references  
**审计日期：** 2026-08-06  
**审计立场：** 以「能否直接交付可落地脚本」为最高标准——不是再评一版研究深度，而是问：**跟组拿着这份规格，能不能稳定交片？**

---

## 0. 总判词（先给结论）

> 这是一份**优秀的「视频提示词制片 OS」规格**，不是完整的「AI 视频脚本创作专家」规格。  
> 画面宪法、连戏、15s 预算、三模式合同——**已超过市面 90% 竞品**。  
> 但若对标专家角色契约（概述 → 分镜表 → 多工具画面提示词 → 配音/字幕/情绪 → 平台调性），当前 SPEC **缺半个片场：声音轨 + 文案轨 + 平台发行轨 + 可复制 prompt 模板本体**。

| 维度 | 得分 | 一句话 |
|------|------|--------|
| 导演/画面方法论 | **9.0 / 10** | 材质宪法 + Memory Pack + 时间码，行业级 |
| 跨镜一致性工程 | **9.2 / 10** | 五层叠甲清晰，对齐 PerfectPhoto 实战 |
| 脚本完整度（专家契约） | **5.5 / 10** | 重画面，轻 VO/字幕/分镜表交付物 |
| 平台与时长规范 | **4.5 / 10** | 只有「≤15s」抽象，缺抖/快/B/YT/视频号表 |
| 多工具提示词适配 | **4.0 / 10** | 提了模型名，无 Cog/MJ/SD/Seedance 分格式 |
| 交互可执行性 | **7.5 / 10** | S0–S12 清楚；缺黄金路径与示例终稿 |
| 可测试/可 QC | **7.0 / 10** | 画面闸门强；脚本层闸门几乎无 |
| 诚实边界/证据 | **9.0 / 10** | scaffold + missing evidence 写得干净 |
| **综合（按「脚本专家」权）** | **7.0 / 10** | **P0 能做导演提示词；还不能叫完整脚本 skill** |
| **综合（按「本定位：导演层」权）** | **8.3 / 10** | 若坚持不做文案轨，应在 SPEC 写死「交付物不含 VO」 |

**建议定调（二选一，必须写进 SPEC 以免角色漂移）：**

- **A. 坚持「视频导演/提示词 OS」** → 在 1.3 排除项明确：`配音旁白成稿 / 字幕时间轴 / 完整分镜表 markdown` 交给姊妹 skill 或用户；本包只交 visual+continuity。  
- **B. 升级为「AI 视频脚本专家同构」** → 补 § 分镜表 · 配音 · 字幕 · 平台表 · 工具格式编译器（见下文 P0-gap）。

当前文案两边讨好：**叫导演却挂脚本专家触发联想**，审计上会判「范围模糊」。

## 1. 专家角色契约对照（硬核对）

专家默认输出顺序：

1. **视频概述**（标题 / 时长 / 风格 / 受众）  
2. **分镜表**（场次 / 画面 / 镜头运动 / 时长 / 时间码到秒）  
3. **画面提示词**（中英对照 + 工具标注 + 画幅）  
4. **配音文案**（旁白 + 字幕 + 情绪/节奏标注）  
5. 短片精简 / 长片多场次  

### 1.1 对照表

| 专家契约项 | SPEC 现状 | 判定 |
|------------|-----------|------|
| 视频概述：标题 | 未列为 Output Contract 必须项 | ⚠️ 缺口 |
| 视频概述：时长 | 有 ≤15s 物理，无「成片目标时长/平台档」字段 | ⚠️ 弱 |
| 视频概述：风格定位 | 进意图诊断/氛围，未固定为交付头字段 | ⚠️ 弱 |
| 视频概述：目标受众 | **未出现** | ❌ 缺 |
| 分镜表（表格化场次） | 有 beats/模式，**无标准分镜表 schema** | ❌ 缺 |
| 时间码精确到秒 | beats 2–3s 原则有；交付表格式未锁 | ⚠️ 半 |
| 画面提示词可直贴模型 | 有 full/compact/chain；**无金样终稿模板** | ⚠️ 半 |
| 中英文对照提示词 | **未要求** | ❌ 缺（若服务出海/MJ） |
| 多工具格式（Cog/MJ/SD/Seedance） | 仅枚举模型名，无 `--ar`/主体动作分层等 | ❌ 缺 |
| 画幅比例字段 | 未进 lock / 概述 | ❌ 缺 |
| 配音旁白 | `audio.anchors` ≠ 旁白文案 | ❌ 概念错位风险 |
| 字幕文本 | **无** | ❌ 缺 |
| 情绪/节奏标注（文案轨） | 有画面节奏铁律，无 VO 情绪轨 | ❌ 缺 |
| 开头钩子/中段信息/结尾 CTA | S0 诊断有结构感，**未固化三幕文案** | ❌ 缺 |
| 平台敏感词/绝对化用语 | 商业绝对化提一句；敏感词表无 | ⚠️ 弱 |
| 事实复核提示 | 未写「生成后请用户复核」 | ⚠️ 弱 |

### 1.2 `audio.anchors` 命名陷阱（P0 概念债）

专家语境下「音频」常指：

- 旁白 VO  
- 字幕  
- BGM 情绪  
- 音效点  

SPEC 里 `audio.anchors` 来自 CyberJ，本质是 **声画可信锚点**（脚步、琴弦、水波），**不是配音脚本**。  

**风险：** Agent 与用户会把「2–4 声锚」误当成「配音写完了」。  
**修补：** 拆字段：

```text
diegetic_audio.anchors[]     # 画面内可信声
voiceover.script[]           # 旁白（可选轨）
subtitles.cues[]             # 字幕时间码
music.mood                   # 可选
```

若产品选择 **永不做 VO**，必须在 Output Contract 写：**不交付旁白/字幕**。

## 2. 按片场岗位逐岗审计

### 2.1 导演 / 摄影指导 — 优秀

**通过项：**

- 先宪法后动作、主花销唯一、焦点接力、合同分离（A/B/C）  
- 名家矩阵「增强运镜而非影评」定位正确  
- 物理微动 + 静止死写，符合可生成性  
- S0–S12 是可跟组流程，不是论文目录  

**扣分：**

- 名家库 v0.1 仍是**纲要**，可编码短语模板不足 → 运行时会退回「堆导演名」  
- `tech.spec` 可降权写得好，但未规定「默认删 ARRI 堆砌」的 compact 策略细则  
- 缺 **首帧可重建** 作为交付硬闸（CyberJ 有，SPEC QC 列表未单列）

### 2.2 美术 / 连戏 — 行业上乘

**通过项：**

- Material Constitution 是真差异化  
- 帽饰独立、道具归属、环境 full_text、字面量焊接、Invariant 拦截  
- 外观 vs 状态定义准确  

**扣分：**

- diff 目前是**文档纪律**，非 script → scaffold 诚实，但交片可靠性依赖模型自觉  
- 缺「产品特写 / 手持 logo」类商业连戏样例  
- 缺 **方言/文字出镜**（招牌汉字）稳定性策略  

### 2.3 编剧 / 旁白 — 明显薄弱

**缺失：**

- 无钩子句模板（前 1–3s 留人）  
- 无信息节拍与画面节拍的对齐规则（VO 说 A 时画面不得抢 B）  
- 无 CTA / 系列预告 / 完播引导  
- 无「口播风 vs 纯视觉无旁白」模式开关  

**对短视频生死线：** 抖音/视频号大量片靠 **口播+字幕** 完播。SPEC 若只服务纯视觉神话片 ok，但触发词含「短视频」会进来大量口播用户 → **体验落差**。

### 2.4 分镜表作者 — 半成品

有时间码思维，缺**表格式交付物**：

| 建议列 | SPEC 是否覆盖 |
|--------|----------------|
| 镜号 | 模式 C 有 shot_index；A 无表 |
| 时间码 | beats 有概念，无统一表 |
| 画面目的 | 弱（在诊断里） |
| 画面描述 | prompt 内含，非表 |
| 镜头运动 | camera.contract |
| 对白/旁白 | 无 |
| 字幕 | 无 |
| 音效/BGM | 仅 diegetic 锚 |
| 备注/风险 | QC 有，未并表 |

**建议：** 增加交付物 `shotlist.md`（即使 A 模式也是 1 行或相位行）。

### 2.5 平台制片 — 不及格（相对专家契约）

专家规范平台时长：

| 平台 | 专家常规 | SPEC |
|------|----------|------|
| 抖音/快手 | 15–60s | 仅模型 ≤15s 切片思维 |
| 视频号 | 30s–3min | 无 |
| B站/YouTube | 3–10min | 无（应强制模式 C 链） |
| 画幅 | 9:16 / 1:1 / 16:9 / 21:9 | **未进字段** |

**正确拆分（建议写入 SPEC）：**

```text
model_clip_max_s     # 单次生成硬上限（如 15）
target_edit_duration # 成片目标（可 45s、3min）
platform             # douyin|shipinhao|bilibili|youtube|generic
aspect_ratio         # 9:16 等
compile_plan         # 如何把 C 链剪成成片（本 skill 只出链，剪辑可选下游）
```

否则用户会以为「PerfectVideo = 一条 60s 提示词」→ 必翻车。

### 2.6 多工具提示词工程师 — 不及格

专家要 **中英 + 工具格式**：

| 工具 | 需要 | SPEC |
|------|------|------|
| Seedance/可灵等视频模 | 主体动作+场景+运镜+风格+时长 | 部分（结构有，无官方槽位映射表） |
| CogVideoX | 动作/场景/镜头/风格/画质 | 未 |
| Midjourney（首尾帧静帧） | 主体+光影+`--ar` | 未 |
| SD/图模 | 正负向、权重习惯 | 负面有包概念，无 SD 语法 |

模式 C 双产物方向对（静帧 prompt + 视频运动 prompt），但 **缺导出适配器** `compile.target = seedance|kling|mj|cog|generic`。

### 2.7 合规与发行 — 弱但方向对

- 成年默认、禁静默换脸、claim guard：好  
- 缺：平台敏感词、logo/商标使用提示、音乐版权不生成声明、深度伪造风险提示（成人类成片）  
- 缺：交付末「请用户复核事实/广告话术」标准 footer

## 4. 交互流程审计（跟组体验）

**好：**

- 1–2 问 + 选项、先推断、冻结仪式、失败说清铁律——导演感对  
- Invariant 表可操作  

**风险剧本：**

1. 用户：「帮我写条 60 秒抖音卖鞋的脚本，要旁白。」  
   - 现状：进 15s 物理 + 可能不产旁白 → **错预期**  
2. 用户：「按这个分镜表出 MJ+可灵。」  
   - 现状：无多工具导出 → **半成品**  
3. 用户：贴完整流体雕塑级需求「直接出」  
   - 现状：快速模式允许，但缺 **单次输出骨架模板** → 质量靠模型临场  

**建议强制的三条「路径卡片」：**

| 路径 ID | 用户类型 | 最少步骤 | 必交付 |
|---------|----------|----------|--------|
| `path.visual_clip` | 纯视觉 5–15s | S0 轻 + 锁 + 一编译 | prompt + bible + QC |
| `path.hook_vo_15` | 口播短视频 | 概述 + 3–5 镜意 + VO + 画面 prompt | **需扩 scope** |
| `path.chain_shortfilm` | >15s 短片 | 模式 C 循环 | 双产物 + shotlist |

## 5. 输出契约审计（相对「可直接落地」）

### 5.1 现有契约优点

- 强制 Bible + 主 prompt + QC，避免只抛一段散文  
- 三模式合同防止物理违法  

### 5.2 建议升级的 Output Contract（脚本专家对齐版）

```text
MUST:
  1. video_overview: { title, platform, aspect_ratio, target_duration, model_clip_budget, style, audience }
  2. visual_bible / lock
  3. shotlist[]: { in, out, purpose, visual, camera, audio_note, vo?, subtitle? }
  4. compiled_prompts[]: { tool, lang_zh, lang_en?, text, aspect }
  5. qc_report

SHOULD (若 path 需要 VO):
  6. voiceover_script with emotion tags
  7. subtitle_cues with timing

NICE:
  8. director_card
  9. negatives_pack
  10. handoff_to_auvideo (optional JSON)
```

### 5.3 时间码精度

专家要求**精确到秒**。SPEC 的 0–3 / 3–6 很好，但应规定：

- 交付时间码格式 `MM:SS–MM:SS` 或 `0:00–0:03`  
- 总和必须 = `model_clip_budget` 或子 clip 时长  
- QC：beats 时长求和误差 ≤0.5s
